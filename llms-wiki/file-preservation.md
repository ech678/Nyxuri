# File Preservation — 判定权归账本，三层机制各司其职

> 跨部署保留用户文件 = **一条判定规则**（#139，所有权 carry）+ **三层实现机制**
> （Dunder / manifest preserve / preserve_values，刻意不合并）。规则的判定权在
> 账本基线，机制的实现各守其位——后人勿把三者"统一"进任何一方。
> 源码：`nyxuri/deploy/atomic.py`（`atomic_replace_item`）。

## 判定规则（#139）：swap 永不销毁引擎解释不了的文件

目录交换组装 `tmp_new` 时，dest 里每个文件按序过三道判据，全部只读现成数据：

1. **名字含 `__custom__`** → 用户的（Dunder walk，机制 1）
2. **在 manifest `preserve` 列表** → 运行时管的（机制 2）
3. **其余文件对照账本基线**（该单元 ledger `files`，即引擎上次铺设的哈希）——
   **领地按账本划，不按 payload 划**：
   - 基线有此路径 + dest == 基线 + 这次 payload 也不含 → 引擎这次不再铺设
     （钩子产物正是此类）→ **随 swap 消失，钩子重放重铺**（KM3 语义恢复：
     产物受管、off 抹白）
   - 基线有此路径 + dest == 基线 + payload 含 → **用新模板**（这才是"更新"）
   - dest == 新模板内容 → 已是目标态，无事可做
   - 基线有此路径但 dest != 基线 → **用户改过 → 原样搬入**（报"你的改动"）
   - 基线没有此路径 → 用户自放 → **原样搬入**（报"用户文件"）
   - 整单元无账本记录（Ghost）→ 来源不明 → 普通 install / on / update 均**原样搬入**；
     只有明确 force 且完整快照成功后，模板具名冲突才采用模板

`__pycache__` 与 `*.pyc` 在两侧 walk 一律剪除——字节码缓存既非模板产物亦非用户
内容，不搬、不进报告（#139 实机报告定案）。

两条不变式：

- **基线不认领个人修改**：已登记路径的个人改动保留旧哈希，doctor 继续报 Drifted；
  外来文件不入账。不能删除旧归属，也不能把个人版本的新哈希写成部署结果。
- **成功部署才增长归属**：on 与 refresh 实际铺设的新文件可登记；force 同样只认领实际
  模板写入的路径，其他外来内容保持原状。

冲突先完整披露。普通操作保留当前内容；用户可明确强制采用模板，但必须先在 Nyxuri 备份区
创建可由 rollback 恢复的版本快照，保存配置、归属、预设、Vault 和受管钩子产物。备份失败
则停止覆盖，普通安装菜单的备份开关不能关闭这一保护。不在应用配置目录生成 `.bak`。

停用按旧部署基线判断：受管且未修改可撤回；已修改先完整复制入 Vault，全部成功后才撤回；
Custom / preserve 只有具备创建来源记录时才归档；名称和目录规则本身不授予撤回权限。
首次部署前已有的 Fisher 插件、个人清单，以及用户后来自行新增的保留名文件，均原地保留
并报告。单文件和 merge 单元
使用同一归档规则。重新启用逐文件恢复，禁止用 Vault 顶层目录替换生活区的同名父目录；
有同名冲突时保全双方，并保留尚未恢复的归档。元数据与重试状态见 [单元模型](unit-model.md)。

保留路径的来源使用独立 `protected_paths` 集合，只登记部署或钩子实际新建的叶节点，
不计算内容哈希、不参与 drift；外部产物由自己的归属清单负责撤回，不重复登记。
来源集合随停用、Vault 恢复与快照保留。旧账本没有该字段时按空集合处理，不按当前名称
补认领旧内容；普通 `files` 已有的归属证据继续有效。

## 共享目录布局迁移

`legacy_targets` 明确列出旧目标与形状。有版本化部署记录时按记录验证；只有旧五字段记录
时按唯一声明的旧默认值补足路径，不能因为新区存在同名文件便把新区当成历史目标。
没有单元账本的旧目录属于未知内容，不自动搬动。壁纸的动态 Pictures 路径始终以旧记录
中的绝对目标为迁移起点。

迁移先创建 v2 快照，保存旧区、新区、单位账本、Vault 与外部产物归属。仅复制有历史基线
的文件和 preserve/Custom，Vault 逐文件合入；旧区其他文件原地保留。新区同名不同内容时
不改文件，返回冲突并保留 `pending=migration`。显式 force 在再次快照后选择旧生效内容；
后续模板刷新仍保护这些个人修改，不能把迁移 force 当成再次采用模板的授权。

所有候选文件在新区复制并验证成功后才删除旧件，复制失败可重试。迁移未完成时普通 off
拒绝撤回，避免清理错目标；rollback 已完成安全快照后，按迁移身份撤回未变复制件，再恢复
旧区、新区、Vault 和原账本。旧五字段快照恢复时清除本轮新增部署元数据。

Portal 的条件文件失效时，只有账本已登记的路径可撤回；已修改规则先放入 Vault，保留旧
基线，重新启用对应桌面后恢复个人版本。明确退役的旧通用 `portals.conf` 只有精确匹配旧
基线才备份后删除；未知或修改版本不再接管，保留并报告。

## XDG 根目录边界

当前仅支持 HOME 下的默认 `~/.config`、`~/.cache`、`~/.local/share`、`~/.local/state`。
对应 XDG 变量未设置或为空时使用默认值；非空必须为绝对路径，允许经 `.`、尾部分隔符与
软链规范化后等价于默认目录。非默认布局在迁移、锁、日志或缓存写入前以中英文错误拒绝，
返回非零；不默默重置变量，也不把自定义 XDG 下的一部分写入默认根目录。
`XDG_PICTURES_DIR` 是图片位置设置，不属于上述四个根目录变量，壁纸仍通过 `get_pics_dir()`
读取 HOME 内的实际图片目录。完整自定义 XDG 根目录支持尚未实现。

## 机制 1：Dunder `__custom__`（模板预留槽的命名约定）

`atomic_replace_item` 在 swap 前扫描 **dest** 里所有名字含 `__custom__` 的文件和目录
（任意深度），把它们的当前内容继承进新部署的 tmp 目录。与 src 是哪个预设**无关**——
不管切到 transparent 还是 default，dest 里的 `__custom__` 都原样保留。
`preserve_custom=False` 是回滚的精确恢复模式，不继承当前配置的自定义内容。

Dunder 的新定位（#139 之后）：**只有模板 include 链按名引用的槽位才需要它**
（如 `input__custom__.kdl` 被 `config.kdl` 引用）。用户**自放的文件不再需要任何后缀**——
账本自动认领为未登记内容。保留与加载解耦不变：引擎只管"保留"，应用各自"加载"
（多文件模块化在主自定义文件里再 `include` 即可）。

test_mode 下跳过 `scratchpad-items__custom__.toml` 和 `orbit-items__custom__.toml`
（test_deploy 的 idempotent 场景）。

## 机制 2：manifest preserve（运行时状态豁免）

`preserve` 的真实语义不是"保留用户文件"，而是**drift 信号豁免**：声明"这个路径的内容
变化不由模板/用户负责，由运行时（脚本、应用自己）管理"——不进账本快照、swap 时从
dest 原样注入（rename 前，inotify 看到的就是最终态，无半态窗口）。典型：
`effects.kdl → effects_normal.kdl/effects_eyecare.kdl` 脚本软链（链接本身保留不解引用）。

条目可以是**目录**（#139 实机报告定案）：整树归运行时管理，部署前整目录注入、
off 进 Vault、目录下所有文件经前缀匹配不入账、不参与 Drifted、不进搬运报告——
整个目录只报一行。典型：fish 的 `functions/`（Fisher 插件领地，模板完全不铺设）。
**禁令**：preserve 目录不得混铺模板 payload——声明即承诺"模板不在此目录铺设任何
文件"，混居会把 payload 永久冻结在旧版（`completions/`、`conf.d/` 正因此不可
preserve，其中 Fisher 的文件继续按 carry 用户文件处理：保护正确，标注近似）。

niri 的 `monitor.kdl` 曾因"被 `config.kdl` 按名引用、不能改名"而走 preserve；
#139 之后它由账本基线判定（没动过 → 跟随模板更新，修掉了 preserve 永久冻结模板
改进的暗病；动过 → gate 提示）。按名引用不再是 preserve 的理由，只有**运行时写它**
才是。例外靠 manifest 声明，不散落代码。

> **竞态消除**：旧实现先 rename 整目录、再事后拷回 monitor.kdl，Niri 的 inotify 会在
> 恢复前读到仓库默认的空 monitor.kdl 导致闪屏。注入在 rename 前完成，看到的就是最终态。

按键级豁免 `preserve_values`：文件级 preserve 的同族扩展，声明形如
`preserve_values = { "noctalia-config.toml" = ["enable_ddcutil"] }`。换入新目录前从旧文件
按段读出这些键的原始写法写进暂存新文件，再整体 rename。键按所在段匹配，旧文件里没有的
键不携带（沿用新模板值），路径越界检查与 preserve 走同一套。键级声明不能豁免同文件的
普通修改：当前整文件哈希与部署基线不同时，普通刷新保留整份文件；只有确认未变或显式
force 才用新模板的其他键。哈希不能单独证明变化仅发生在声明的键上。

## 为什么三套实现不合并

| | Dunder | preserve | carry 判定 |
|---|---|---|---|
| 触发 | 魔法文件名 | 显式声明 | 账本基线比对 |
| 谁的 | 设计预期用户填的槽位 | 运行时（脚本/应用）写的 | 引擎铺设之外的一切 |
| 入账 | 否 | 否 | 只记引擎铺设侧 |

三套服务三种真实来源（模板预留槽 / 运行时状态 / 用户心血），实现各守其位；
统一会互相破坏（Dunder 改名破坏 include、preserve 入账会把脚本切换误报成漂移、
carry 吞掉按名保留）。

## 运行时写入与主配置变换

独立渲染输出保留首次原值与最后写入身份，默认不能覆盖未登记的不同内容。蓝图新建的初始
色板可由事务提供精确的新建证明后交给渲染器；从 Vault 恢复的个人文件不算模板新建。
主配置内的受管变换仍沿用普通文件基线：当前内容与基线相符才可写，写入后更新该路径的
哈希。刷新源码重建可逆原值，停用先撤回变换并重读基线，再判定是否需要归档。这样既能
继续升级模板，也不会把恢复后的原模板误当成个人修改；完整归属契约见 [单元模型](unit-model.md)。

## 模板冻结（安全代价）

仓库 ship 的 `__custom__` 模板（`__custom__.kdl`、`__custom__.conf` 等）纯注释，第一次部署
进用户家后被 Dunder 当用户文件保留——开发者后续改进模板内容**到不了已安装用户**。这是
"一旦用户可能改过就不碰"的安全代价。因为模板只有注释无生效配置，冻结的只是注释 wording，
不影响功能。同理，carry 使"用户改过的受管文件"停止跟随模板（改进需审阅后 `--force`
采纳；off/on 恢复个人版本）——诚实的代价：引擎不假装会合并配置。

## 存储路径与命名边界

Nyxuri 元数据在配置域的 `~/.config/nyxuri/`（backups、presets、active 状态、hooks）
与状态域的 `~/.local/state/nyxuri/`（账本、Vault、外部产物归属与恢复记录）保存。
`~/.config/<app>/` 里不塞 Nyxuri 自己的东西——`__custom__` 是约定保留名，属 app 配置一部分，
不算"拉屎"。`manifest.toml` 是仓库元数据，deploy 时被 `_deploy_ignore_factory` 跳过，不进 dest。

## 动词语义表（谁传什么立场）

| 调用方 | carry | 基线 | unknown 立场 |
|---|---|---|---|
| `update` / `unit_refresh`（普通） | ✓ | 旧部署哈希 | True；仅已启用单元，修改与外来文件保留 |
| `update --force` / `on --force` | ✓ | 模板优先 | False；完整快照成功后覆盖模板冲突，额外文件仍保留 |
| `install` / `on` | ✓ | 旧部署哈希或空映射 | True；没有归属证据时保留 |
| `nyxuri test` | ✓ | 账本 | 按隔离验收流程指定 |
| 预设切换 | ✓ | 旧部署哈希 | 与 on 共用事务，只允许已启用目录单元 |
| 零件切换 | ✓ | 零件目标的部署哈希 | 冲突保留并取消切换，force 先备份；其他文件不重新入账 |
| 回滚 | 精确恢复 | 快照同时恢复文件和归属 | 先保存当前恢复点，再恢复所选快照，不套用当前配置carry |

原语默认 `carry=False`：裸调用保持纯模板替换语义，工作流显式选择立场。
