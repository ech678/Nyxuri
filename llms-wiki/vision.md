# Nyxuri 设计哲学与架构愿景

> 极简不是风格，是秩序感：几何精度（对齐规整）+ 做减法（砍掉一切不必要的）。
> 本页是全项目哲学的唯一权威：ROADMAP 以五条标准为阶段验收门禁，其余文档只引用不复述。

## 1. 简洁的五条标准

简洁的判据不是「看起来干净」，而是五条可检验的标准：

1. **真诚透明**：不把乱七八糟的东西塞进暗格再漆成纯白。系统完全可知、完全可见，
   与人之间没有高高在上的隐瞒。落到机制：一切副作用必须声明（manifest）；
   一切开关先披露后执行、执行后交报告（知情协议）；doctor 持续对账
   「声明状态 vs 实机状态」。
2. **绝对主权**：用户对任何部分拥有完整的开、关、装、拆决策权，不是提线木偶。
   落到机制：每个单元可独立开关，装其中一件不需要装任何别的；系统提议，用户决策。
3. **骨架包容**：不靠驱逐外界维持洁癖，像一副从容克制的骨架，托得住任何风格的外部
   内容，容得下变数、经得起杂音。落到机制：未知文件容忍（Dunder / manifest
   preserve）；坏单元只降级自身不拖垮目录；缺可选依赖局部降级，可选性不绑架核心。
4. **轻盈生长**：可以随心添加能力，系统永远轻巧干净，不因功能丰满而臃肿迟钝。
   落到机制：新单元接入 = 加目录 + 加 manifest，零内核改动；未启用单元零加载；
   停用即退干净，对空间与资源本能克制。
5. **通用自然**：不发明晦涩别扭的私有规则来标榜自己，全程使用最自然、最流通的
   通用语言。落到机制：动词是通用词，元数据是通用 TOML，全库只有四个术语——
   单元（可开关项）、内核（registry · resolver · transaction · ledger）、
   源（单元来处）、manifest（单元声明书）。

## 2. 终态图景：桌面插件市场

Nyxuri 是桌面插件市场，不是安装器；安装器只是它的一次性引导。

```
Nyxuri = 内核（registry · resolver · transaction · ledger）
       + 目录（万物皆单元，manifest 全量声明）
       + 市场（TUI 目录浏览器为主界面，CLI 等价动词）

单元 = kitty 配置 / fcitx 皮肤 / greeter / 壁纸包 / Shell 域 / ……
状态 = off ↔ on 原子切换：切换前快照 + 准确披露，切换后交报告
```

- **空间对偶**：仓库源码（`configs/`）是只读蓝图，用户系统（`~/.config/`）是生活
  空间，中轴（`deploy.atomic`）以哈希比对与原子替换连接，互不侵犯。
- **四象限对齐**：外部供给（`pkg`）、内部渲染（`deploy`）、外部诊断（`doctor`）、
  内部回溯（`state`）各司其职，消除缝合怪与特判特例。
- **单元内三层叠加不变**（默认 ← 预设 ← `__custom__`）；单元间是市场开关，两层正交。
- **内核边界钉死**：`deploy.atomic`、i18n、registry、ledger 是骨架，不是插件——
  内核自身插件化是过度间接，骨架反而碎。
- **Shell 是完整宿主**：内核（装配 / 生命周期 / Action Gateway / IPC）零业务，
  一切功能域是模块；一方模块与第三方单元同契约，没有特权公民。市场 ↔ 宿主桥接
  只复用 Shell 既有 IPC 通道；单一开关真相：所有界面都是同一张开关的皮。

## 3. 演进原则

- **底座先行、契约冻结**：先搭齐底层公共接口与测试样本并冻结契约，再逐一接入具体桌面业务。
- **一切皆可选 (Everything is Optional)**：Shell 与合成器（Niri、Hyprland 等）按需组装，不强制死锁单一组件。
- **纯标准库驱动**：守护纯 Python 标准库零依赖基准，保证 `arch=('any')` 免编译分发与秒级测试闭环。
