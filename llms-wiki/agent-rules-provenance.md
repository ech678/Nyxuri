# Agent 规则溯源、回归集与被拒绝规则

> 本文记录 `AGENTS.md` 与核心开发约束的历史事故起源、防回归测试映射，以及经评估后明确拒绝引入的无效规则。

---

## 1. 规则来源与真实事故映射 (Rule Provenance)

| 规则 / 约束 | 来源事故 / 触发背景 | 防护手段 / 契约测试 |
|---|---|---|
| **测试隔离 (TempEnv)** | 历史提交 `9cb1e0a` 之前，某些测试曾把实机仓库 `configs/niri/config.kdl` 覆写为测试桩文件，污染真实工作区。 | `tests/utils.py:TempEnv` 强制隔离，契约测试检查工作区纯净。 |
| **测试深度 (命令形状断言)** | 在测 `safe_git_pull` 时，若只 mock 高层 `_run_git_transfer`，会跳过 `_with_git_progress` 的参数变形逻辑，导致参数错误未被捕获。 | 命令构造测试必须断言完整的 `args` 形状列表，禁止仅断言布尔返回值。 |
| **Dunder Protocol 自动保留** | 早期部署直接覆盖整个 `~/.config/<app>`，导致用户编写的快捷键或自定义配置在更新时被暴力清洗。 | `nyxuri.deploy.atomic` 实现基于 Dunder（`__custom__`）的保留策略，`test_deploy.py` 严格覆盖。 |
| **物理隔离 (禁止软链到 ~/.config)** | 过去曾使用符号链接直连仓库文件，导致开发中未验证的草稿改动立即影响用户桌面运行，或用户修改反向污染 Git 树。 | 部署仅允许通过 `atomic_replace_item` 物理复制；契约测试验证 `~/.config` 外部文件非软链。 |
| **mktemp 陷阱规避** | Bash 中执行 `export VAR=$(mktemp)` 会静默吞掉 `mktemp` 命令失败时的非零退出码。 | 要求拆解为 `VAR=$(mktemp) || exit 1` 两行声明，ShellCheck 静态把关。 |
| **GPU 变量不自动改写** | 过去部署引擎曾根据 PCI 设备自动生成 NVIDIA 专用环境变量，引发集成显卡/双显卡启动冲突与黑屏。 | 拔除部署硬件驱动改写，默认配置不硬编码驱动变量，见 `llms-wiki/nvidia-patch.md`。 |

## 2. 典型回归测试集 (Regression Scenarios)

以下场景代表历史上 Agent 或开发者容易踩坑的边界，每次重塑或修改规则时需重点检验：

1. **测试写入实机配置回归**：
   - 检验：运行完整单测套件 `python3 -m unittest`，确认 `git status` 依然呈现工作区干净，无任何临时文件写入 `configs/` 或真实 `~/.config/`。
2. **命令参数丢失或构造退化回归**：
   - 检验：`tests/test_network.py` 与 `tests/test_pkg.py` 验证所有外部命令构造（curl 超时、git 进度、pacman/shelly 参数）。
3. **预设切换保留自定义与零件插槽目标**：
   - 检验：`tests/test_preset.py` 验证切换预设时用户 `__custom__` 与 `[parts.*]` 声明的目标文件完好无损。

## 3. 被拒绝的规则记录 (Rejected Rules)

以下规则曾被提议，但经评估会导致负面收益或熵增，明确拒绝引入：

- ❌ **“每次任务前由 Agent 自动重写全量 Wiki”**：
  - *拒绝理由*：导致文档严重脱节或充斥 AI 臆想套话；Wiki 是精炼的架构契约与设计原因，必须以真实源码契约测试为底座进行精准同步。
- ❌ **“将所有配置项全部抽象为动态 Python DSL”**：
  - *拒绝理由*：违背做减法原则；90% 应用只需纯静态文件原子复制，引入过多 DSL 会带来陡峭的维护成本与隐式错误。
- ❌ **“使用全局异常捕获静默跳过所有部署失败”**：
  - *拒绝理由*：破坏了系统的可预测性与白纸洁癖；部署失败必须原地报错、回滚并保留现场供排查。
