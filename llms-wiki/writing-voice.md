# Writing / Voice — 文案风格与语调

> 文字应该像这个项目本来就会这么说。Nyxuri 不是企业产品，也不是 AI 生成的设计稿。

---

## 核心原则

* **清楚优先，简洁其次**：能短就短，但不要为了短而变得生硬、含糊或失去语气。
* **保留人格**：允许自然、灵动、锋利、轻微幽默，甚至偶尔不那么“规范”。
* **少改比乱改好**：原文已经自然、准确、有项目气质时，不要为了统一风格强行重写。
* **具体胜过漂亮**：少说“提升体验”“更加稳定”“无缝”“强大”等空话，直接说发生了什么。
* **像人说话**：避免模板句、万能总结、过度解释、机械的“三段式”、刻意正式和明显的 AI 套话。
* **不要为了显得专业而失去自然**：技术术语可以用，只要读者真正需要它。

---

## 按场景调整

| 场景 | 方向 |
|---|---|
| CLI / 错误 | 清楚、直接、克制 |
| 确认 / 危险操作 | 说明后果，让用户做决定 |
| TUI | 清晰为底，可以有一点 Nyxuri 的个性 |
| README | 自然、有观点，不写营销稿 |
| 注释 | 像作者留给未来自己的便签，解释“为什么” |
| Changelog | 只写用户真正感知到的变化，短，但不要僵 |
| 安装器 | 流畅、安静；只有真正需要用户决定时才打断 |

---

## AI 去味检查清单

修改文案或代码注释时，优先自查：

1. 这句话原本有没有必要改？
2. 是否只是换成了更“规范”的说法？
3. 是否出现了 AI 常见的套话或重复排比结构？
4. 读起来像不像一个真实作者写的？
5. 删掉这句话后，核心信息真的会损失吗？

> 极简是秩序，不是沉默。
> 规范是底线，不是人格。
> **让每一句话都像 Nyxuri。**
