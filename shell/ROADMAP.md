## 序言：我们要什么，不要什么

在 Wayland 与 Niri 的生态里，我们追求的从来不是"能跑就行"的拼凑之作，也不允许系统沦为法外之地的资源黑洞。

极简是秩序，是几何精度的对齐与克制的减法；完美主义则意味着核心主干零将就、零失控。

**Nyxuri Shell** 的使命，是以 [[StatIndet/quickshell](https://github.com/StatIndet/quickshell)](https://github.com/StatIndet/quickshell) 惊艳的视觉语言与流体交互为母体，就地进行彻底的净化与重构，锻造一套轻量、纯净、结构严整且绝对可控的现代化桌面外壳。

眼下这一步，只是整段旅程的起点：一次纯粹的架构与启动奠基。它必须被当作日后无数次功能移植与生态融合的地基来对待——容不下半点侥幸，唯有完美。

## 一、母体与渊源

| | |
|---|---|
| 上游母体 | [[StatIndet/quickshell](https://github.com/StatIndet/quickshell)](https://github.com/StatIndet/quickshell)（代号 Clavis） |

**为什么选它？**

它在 Quickshell 之上构建了一套极具现代感、质感细腻、动效丝滑的桌面界面，代表了当前 Wayland QML 桌面外壳在审美与交互维度的顶尖水准。

**为什么必须动刀？**

光鲜的表象之下，它是一头充斥着熵增与失控的高熵巨兽：

1. **开机全量常驻** — AppShell 一启动，无论用户是否需要，壁纸、Dock、卡片、侧栏、录音、天气、频谱便全部实例化；
2. **死锁式强依赖** — 缺一个 Cava 或某个特定 C++ 插件，整个 Shell 便崩毁在入口处；
3. **杂质与 Slop 丛生** — 内嵌数 MB 字体，藏匿未经审计的常驻子进程与网络请求；
4. **虚假关闭** — 大量面板的"关闭"不过是把 UI 设为 `visible: false`，后台仍在悄悄吞噬 CPU、内存与连接。

## 二、核心教训：为什么严禁"另起炉灶"

历史已经给出教训：**严禁**开一个空目录，从原版一点点搬运代码。

QML 的灵魂在于其深度的隐式上下文、组件级联、动态作用域与属性绑定。一旦脱离完整上下文去"从零开荒"、"切片移植"，无论是人类还是 AI，都会陷入疯狂发明虚拟胶水（shim）、猜测环境、破坏原生绑定的恶性循环——最终产出一堆看似轻巧、实则无法运行的报废代码。

**正确的战略：**

我们绝不另起炉灶，而是将 [[StatIndet/quickshell](https://github.com/StatIndet/quickshell)](https://github.com/StatIndet/quickshell) 完整平铺进项目，作为活体起点。

> 我们是在一整块完整的大理石上雕刻，而不是在太平间里缝合科学怪人。所有重构，都在原版的代码树里就地发生。

## 三、四大设计哲学

### 1. 彻底"去 Slop"（除熵与净化）

- 剔除私货资产——砍掉原版内嵌的数 MB 字体（如 Google Sans），优雅接入系统级字体回退；
- 剔除流氓常驻——拔除一切无节制的常驻后台进程（未启用功能时的键盘监听、音频嗅探、无序网络轮询等）；
- 清理废弃代码——清除原版残留的调试代码、无意义脚本与死数据。

### 2. 极致的简洁性与优雅性（骨骼重构）

- **消灭黑盒单例**——废除跨层随手调用全局 Service 的野蛮写法，重构为显式依赖注入与单向清晰数据流；
- **统一动作契约（Action Gateway）**——UI 视图只负责响应输入与呈现画面，严禁在组件深处直接起进程、写文件；所有桌面意图统一经由 Action 网关收敛执行，使每一次状态变迁都规整透明、可被审计。

### 3. 高可扩展性（模块自治）

每一个功能都是一个边界清晰的自治插件——高内聚、低耦合，具备自洽的参数配置与生命周期，即插即用，接入新功能不波及主干。

### 4. 最小化演进与视觉守护（保住灵魂）

- **先最小化**——以最小的核心功能极速冷启，绝不让非必需组件绑架基础体验；
- **保住灵魂**——去 Slop 与重构骨架，绝不意味着把界面搞丑或简陋。原版精美的流体动画、设计精度与视觉质感，必须原汁原味地保留。

## 四、当前阶段的战略红线

> **当前死命令：玩具全部靠边站，全力攻克"启动"与"架构"。**

必须清醒地认识到：**这一阶段只做一件事——把地基浇筑完美**。

Nyxuri Shell 的生命历程远不止于此。未来会不断从其他优秀的 Quickshell 生态项目中吸收、移植功能——一块状态栏组件、一种通知交互、一套动效方案——持续并入这套骨架。每一次移植，都会顺着今天定下的 `app/`、`modules/`、`shared/`、`native/` 边界与 Action Gateway 契约生根发芽。

**地基歪一寸，后面的每一层都会歪一尺。** 今天在架构与启动上留下的任何将就、任何"先跑起来再说"的侥幸，都会在日后每一次功能移植中被无限放大、反复偿还。所以这一步不是"能用就行"的过渡稿，而是必须经得起未来无数次嫁接的完美底座——边界要清晰到毫不含糊，契约要严谨到无可辩驳。

**明确范围边界**

Cava 频谱、复杂天气地图、歌词服务这类附带重型原生插件、网络依赖或外部音频依赖的功能，现阶段一律不做，全部封存。不是因为它们不重要，而是因为地基未稳之前，任何附加物都只会掩盖架构本身的缺陷。

**当前唯一交付标准**

1. **干净稳定的冷启动** — 仅具备基础运行环境即可秒级亮屏，零报错，不依赖冷门原生插件；
2. **立住规整的四层架构** — 将上游混乱的源码树，在原地梳理、重构为清晰的标准物理架构，且这套边界必须足够坚固，能够承接未来源源不断的功能移植而不需要推倒重来。

## 五、目标物理架构蓝图

**约定的物理落点**：在项目根目录下新建 `shell/` 目录，作为整套架构的物理容器——上游代码平铺于此，后续所有重构均在这个目录内就地发生，不与仓库根目录下的其他内容混杂。

在原有代码树上，逐步重构提炼为以下四大物理分层：

```
shell/
├── app/       # 调度中心 (Orchestration)
│              # 顶层装配、Wayland/Niri 环境感知、全局快捷键与统一生命周期调度
│
├── modules/   # 功能自治域 (Isolated Modules)
│              # 状态栏 (Bar)、启动器 (Launcher)、通知中心 (Notifications)、
│              # 会话控制 (Session)、锁屏 (Lock) 等各立门派
│              # 业务逻辑与专属服务完全内聚，各域自生自灭
│
├── shared/    # 纯粹共享层 (Purity Shared)
│              # 经过严格审计、跨模块复用的原子 UI 控件、几何动效与纯计算工具
│              # 严格保证纯净性：绝无外部副作用、不发请求、不写文件
│
└── native/    # 底层插件桥梁 (Native Bridges)
               # 必要的 C++ 扩展，必须实现"优雅降级"契约：
               # 插件就绪则发挥全部性能；环境缺失则静默降级，绝不拖垮整个 Shell
```

**生命周期的自治原则**

- **按需唤醒** — 模块未被使用时不占用资源；
- **真实销毁（Hot Teardown）** — 用户或系统停用某模块时，窗口销毁、定时器终止、连接断开、子进程终止，内存彻底归还系统；
- **干脆退场** — 切换回备用 Shell（如 Noctalia）或退出时，没有双状态栏，没有幽灵进程，来去自如。

## 六、贡献者实操 SOP

若你要参与 Nyxuri Shell 的重构，请严格按以下步骤行动：

1. **以母体为基准** — 在项目根目录下新建 `shell/` 目录，将 [[StatIndet/quickshell](https://github.com/StatIndet/quickshell)](https://github.com/StatIndet/quickshell) 的基准代码完整平铺进去，直接在此基础上工作，不新建孤立项目。
2. **拔刺脱困，实现秒级启动**
   - 斩断 Cava、天气地图等非核心插件与主入口的强绑定，改为空实现桩或可选加载；
   - 砍掉内嵌字体，接通系统字体回退；
   - 确保执行启动命令时，窗口能瞬间、稳定、零崩溃地呈现在屏幕上。
3. **就地重塑分层**
   - 梳理混乱的 Modules/Services/Common，逐步将它们归位到 `app/`、`modules/`、`shared/` 的规整边界中；
   - 消除组件对全局单例的直接引用，改用属性传递与单向数据驱动。
4. **驯服后台副作用**
   - 检查每一个 Timer 与 Process，为其加上生命周期锁；
   - 验证关闭逻辑：界面收起时，后台活动必须同步熄火。
5. **严禁走火入魔**
   - 专注于启动、架构与去 Slop；
   - 不要提前搬运复杂玩具，也不要为压缩体积而破坏原版已调优的视觉动效。

## 根目录 ROADMAP 相关计划原文

### 开发 Shell 时

- [ ] **原生内置启动器、壁纸管理与 M3 调色引擎**：原生承载应用启动检索与壁纸管理；算法直出同构 `palette.toml`，在自研 Shell 模式下无需安装任何外部 Python GUI 伴生脚本；
- [ ] **兼容 Noctalia Template 系统 (TemplateAdapter)**：支持其 Jinja 风格模板规范与变量命名空间，让现有 GTK CSS、Fcitx SVG、Kitty、Starship 和用户模板无需重写；
- [ ] **Shell 生命周期与动作响应网关对接**：打通与 `session-shell.sh` 的守护拉起及 `shell-action.sh` 的 6 大标准动作（`launcher` / `session` / `settings` / `clipboard` / `lock` / `wallpaper-random`）IPC/CLI 接口，外围快捷键零改动即刻响应。

### 开发 Shell 后：直接相关

- [ ] **双 Shell 切换 (`nyxuri shell set`)**：支持 `nyxuri shell set <noctalia|custom>` 或快捷键切换 Noctalia 与自研 Shell；
- [ ] **Noctalia + Wallpaper Picker 协同方案稳固验收**：验证 Noctalia 模式下伴生套件的按需部署与运行，确保双轨方案互不干扰、各自纯白；

### 宿主后续事项：保留关联

- [ ] **TUI 视觉风格化与纯净感 (Terminal Rice)**：接入 Alternate Screen Buffer（`\033[?1049h/l`）保护终端历史（运行 `doctor` / 查看快照不被抹除），DEC 2025 协议消除高刷频闪撕裂，引入单行微动 Zen Spinner 就地收拢命令滚屏日志；
- [ ] **多合成器 (Multi-WM) 架构解耦与驱动抽象**：构建 `CompositorDriver` 驱动抽象层，实现热重载、浮动便签与屏幕探测的跨合成器适配（Hyprland/Sway 等按需扩展），`doctor` 诊断与 `greeter` 会话自适应；
- [ ] **安全 Downdate 体系（高级储备）**：落地基于现场快照优先还原与 Git 逆向检出的安全版本回退机制。

P0 调查默认修整现有代码，复用有效模型和协议。界面/普通逻辑使用 QML/JavaScript，

不把“源码里有高级功能”直接等同“必须换魔改 Niri”。

## P2：四层与真实生命周期

前置：P1 闭环可用。按一个完整功能域迁移和验收，再迁移下一个；不先搬完目录再修绑定。

| 任务 | 改动边界与交付物 | 验收 |
| --- | --- | --- |
| P2-01 装配与注入 | app 持有协调和环境；模块通过窄属性/接口获取依赖 | 迁移域不再随手访问其他域 singleton；上下文和绑定可运行 |
| P2-02 纯共享层 | 审核 Widgets/Components/Common；提取控件、尺寸、动画、纯函数 | shared 不持有文件、进程、网络、环境或业务连接；保留几何精度 |
| P2-03 动作与资源归属 | Action Gateway 收敛意图；backend 执行副作用并登记 owner | 参数数组调用；失败可追踪；避免巨型网关包揽全部业务 |
| P2-04 自治加载与销毁 | 面板关闭动画后卸载；停用停止任务、连接、请求与子进程 | 重开不受旧回调污染，关闭与停用语义分开；基础服务按真实消费者保留 |
| P2-05 可选 native | 拆分目标与消费者；只保留已证实的标准 Niri 对接 | 插件缺失局部降级；没有魔改要求；已有取消/消费者机制不被无意义重写 |

连续开关/停用测进程、连接、请求、计时器与稳态资源，不用匹配源码结构的伪测试。
Qt/字体缓存不承诺每字节即时返还，重点证明专属资源消失且稳态不持续增长。
