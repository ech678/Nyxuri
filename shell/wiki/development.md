# Nyxuri Shell — 开发与调试指南

## 当前可用与不可用

当前处于详细计划阶段。母体尚未完成启动修复；产品名 Nyxuri Shell，标识 nyxuri-shell。
上游开发文档仍含 clavis、源码软链和 key-cli 流程，不能直接当作 Nyxuri 安装教程。

本机已核实 QS 0.3.1 的 --path、日志和 IPC 工具。下面命令是已有工具使用方法，
不是已完成开发入口；原版母体目前会因 Clavis.Niri 缺失而退出。

在仓库根目录：

```bash
# 真实视觉预览：仅在确认旧 Shell 互斥及开发数据隔离后使用
qs --path ./shell --no-duplicate --log-times -v

# 查看选定配置日志与可用 IPC
qs log --path ./shell --follow
qs ipc --path ./shell show
```

--no-duplicate 只避免该 QS 配置重复，不阻止同时运行 Noctalia，也不隔离用户数据。
当前原版 Paths 仍指向 clavis 用户目录，因此不要把上述命令理解成可安全日用的启动方案。
未来入口就绪前，解析探测沿用临时 HOME/XDG、禁真实 session bus 和 offscreen 的方式。
离屏不验证 Wayland 锁屏、视觉或切换，日志显示配置错误不等于图形会话验收。

已有阻断：入口缺 Clavis.Niri；CMake 全量 configure 缺 Cava 开发接口；上游检查脚本
格式基线不一致。日志与证据见 [审计](audit.md)。不为完成计划安装依赖。

## 日常开发循环

每轮回答：现在什么能用，这一轮证明什么，失败回到哪里。

1. 查看工作区、当前可运行检查点及工具阻断，确认本轮改动不会混入其他工作。
2. 选择一个行为目标，记录范围、验收方式与恢复点；不要只写“整理架构”。
3. 定向调查加载闭包、消费者、构建依赖和副作用；查到足以实施就动手，新增关键未知再补调查。
4. 修改或实验，再按影响验证。可以大幅尝试，不把“一次只改一个变量”设成硬限制；
   问题难定位时拆开依赖、字体、装配与迁移，缩小比较范围。
5. 记录真实结果、遗留问题和下一步。失败实验也记录结论，不把中间状态当作完成。

P0 冻结启动必需决策，后续域在迁移前继续调查。四层边界保持清楚，具体接口由真实接入
检验，不靠文档完整度证明扩展性。路线图维护状态，本页维护流程，审计保存事实与证据。

## 分支、实验与合并

建议长期开发分支为 `feat/nyxuri-shell`，尚未创建。所有实验直接在该分支进行，
不要求另开短期实验分支。分支只隔离代码历史，真实配置、依赖与后台服务仍共享本机，
不会因离开 main 获得额外修改权限。

- 允许大胆方案、大幅修改和暂时不可运行；实验前保存已知状态，注明基准提交。
  有未提交工作时同时说明其保存方式，单个 commit 不能恢复未跟踪文件。
- 当前母体大量源码尚未跟踪。后续首份源码提交单独保存完整母体和来源，避免与改造混杂。
- 实验结束记录结论、遗留问题和恢复位置。可运行检查点必须通过相关验收，
  后续迁移从检查点推进；不要求每个中间状态都绿。
- 按已验收阶段合并回 main，不必等整个 Shell 完成。合并结果须保持宿主可用，
  未实现能力明确标注，失败路径可恢复，无无关改动、调试残留和生成物。
- 提交需用户明确要求；本文不是创建分支、提交、重写历史或删除用户工作的授权。

## 计划中的舒适开发流程

[P0-07/P1-06](../ROADMAP.md) 冻结并实现下面流程，命令名尚未决定：

1. 检查已有 Shell、图形环境、能力与构建状态，明确将预览哪个实例。
2. 隔离开发设置/状态/缓存与日志；源码使用显式路径，不软链、不改生产偏好或配置。
3. 通过统一切换机制进入开发预览，确认首帧和动作就绪，不同时启动两套栏或通知服务。
4. 修改 QML 后观察热重载与日志；修改 C++ 后构建受影响目标，再完整重启实例。
5. 使用状态/IPC 检查目标实例和不可用能力；多实例时按明确实例身份选择日志，避免误看旧日志。
6. 停止开发实例并恢复进入开发前的 Shell；失败日志保留，恢复失败明确报告。

即时切换、启动与开发流程共享真实生命周期规则，不维护两个互相冲突的实例管理器。
未登录图形会话、已有不受管 Noctalia、锁屏状态未知和旧 custom 入口不支持健康接口的
情况，须在启动计划中明确处理，不能要求用户靠手动 pkill 修复。

P1 先在隔离测试会话证明显示、输入、本地应用入口、ready 与退出，再接管日用会话。
上面完整切换流程在第二检查点验收，第一检查点不提前宣称可日用。

## 视觉、资源与清理证据

视觉改动前保存可获得的截图、短录屏与机器、版本、分辨率、缩放、字体信息。
母体暂时不能运行时区分上游参考与本机实测，注明缺失证据，不凭记忆确认视觉保真。
检查对齐、裁切、图标完整、字体回退、动画连续性和输入反馈。系统字体替换允许字形变化，
但不能接受布局破坏；视觉与架构冲突时记录阻断和候选方案，不默默降低质量。

首次可运行即记录首帧与 ready、空闲 CPU/RSS、专属进程和退出残留，固定比较环境；
正式 p50/p95 与冷暖缓存统计在 P6 完成。重复操作观察后半程稳态，不把 Qt/字体缓存
直接判成泄漏。数据不支持时不承诺秒级或零泄漏。

清理记录缩小的加载闭包、停止的后台、退出默认构建的依赖和删除的源码资产；
迁移记录消除的跨域调用、注入接口、资源 owner、释放路径与移除的旧实现。
封存清单列出保留理由、入口、依赖、检查范围及重新启用条件，不能用封存代替永久清理。
证据注明版本、命令、环境、结果和未解决问题；避免提交含私人路径或用户数据的日志。

## 调试层次与检查

| 改动/问题 | 调试方式 | 注意 |
| --- | --- | --- |
| QML 布局/动画/文案 | 真实 Niri 预览、日志、保存热重载 | 对照上游几何、字体裁切和动画；只格式化改动文件 |
| import/插件缺失 | 读第一条加载错误，检查真实组件加载闭包与构建 import 路径 | 不手写 qmldir、不伪造 plugin，不把隐藏当可选解析 |
| C++ 模型/协议 | 配置/构建受影响目标，已有逻辑/协议测试，完整重启 | 需要时使用已有 debugger；不为普通 UI 引入额外 native |
| 后台/关闭/切换 | 完整退出/重启、进程与连接观察、重复开关 | 热重载成功不证明退出清理；不杀其他实例或用户应用 |
| 锁屏/多屏/通知 | 真实原版 Niri 会话验收 | offscreen 与普通窗口不能替代安全锁或通知服务互斥 |
| 宿主命令/部署 | TempEnv 行为测试、参数数组断言、沙箱部署 | 不写真实 ~/.config，不通过 source matching 冒充行为测试 |

上游 scripts/dev/check.sh 尚需确认宿主路径与变更选择；当前不能承诺一条 check 已覆盖全部。
文档修改检查一致性、链接和空白；日常实现按风险选择上表验证，阶段完成时执行宿主
规定的完整检查与受影响上游检查。工具缺失记录阻断，不安装大工具链来掩盖未验证行为。
生成物写独立 build/staging，运行日志注明时间、实例与失败阶段，限制增长。
P0 调查后在此补齐实际命令、路径和恢复步骤，撤下过期建议；未实现工具始终标为计划。
