## 3. 按域恢复，先修输入与通知

每个域采用同一顺序：阅读原实现及依赖 → 对照当前净差异 → 复现 → 最小适配 →
行为/视觉对照 → 记录证据。保留原组件树、状态机、绑定、尺寸、动画和资源；
路径、显式注入、网关/backend 归属只在必要处调整。不能复制单个叶子后重造其上下文。
若当前新增实现替代了原组件，优先接回原实现；在消费者切换且验证通过后再移除被替代代码。
不把整个旧目录搬回生产树，不留下两套同时接收输入或通知的实现。
架构适配造成体验损失时修正适配方式，不能以四层边界为由删掉原行为或降低视觉质量。
每批开始前先完成对应矩阵行及依赖映射；复用受阻时记录具体文件、接口和最小替代范围，
不能直接用新写组件跳过原上下文。

### 第一批：Bar 输入闭环

读取原版 `Modules/Bar/QuickSettings/`、Bar 装配与复用输入控件，并对照
当前 `modules/bar/`、`app/ActionGateway.qml`、音量/亮度等 backend。
追踪“指针命中 → wheel handler → delta/方向/步长 → 网关参数 → backend → 设备变化 → UI 回读”，
逐段观察实值，检查覆盖层、事件接受、注入对象、单位与异步回写；这些是排查点，不是已确认根因。
所有原版可滚动区域逐项验收，不能只测试快捷设置滑条。
验证正反滚动、限值、静音、点击、拖动、设备切换、缺设备与重复开关；
同时保留原版 hover、图标、刻度、布局和动画。

### 第二批：通知视觉与生命周期

先找出原版真正的通知展示链及背景/窗口宿主，不预设新建 PopupHost 就是正确答案。
复用原通知卡片、背景绘制、主题透明度、圆角、阴影、动画与几何算法，
检查当前主题注入、LayerShell 锚点、逻辑像素、输出选择与 Bar 保留区域。
定位规则以原版和配置语义为准，不凭肉眼添加固定偏移补丁。

在同分辨率、缩放、字体、主题、Bar 位置下记录前后截图与边界距离；
覆盖各受支持 Bar 方向/位置、多屏、不同缩放和通知设置位置。
验证短/长文、图标、操作按钮、超时、关闭、替换、紧急等级、勿扰、堆叠、
历史与重启持久化，具体支持语义以原版盘点结果为准。
关闭历史面板仍能接收；面板专属资源释放；双 Shell 切换没有 D-Bus 争抢。

### 第三批：其他基础域与六动作

按盘点矩阵逐页恢复设置、启动器、剪贴板、会话与剩余基础交互。
优先复用现有有效原生模型，不凭抽象接口重写数据源。
六动作从快捷键/CLI 验证到真实窗口、数据变化与关闭结果；壁纸动作要有实际变化证据。
Noctalia 的宿主动作语义需对齐，不要求两套 UI 外观相同，也不宣称百分之百行为一致。

### 第四批：锁屏安全与整体验收

复核真实 session-lock 与 PAM 链，测试错误/正确密码、取消/重试、多屏与输出变化，
锁屏时拒绝切换；隔离测试会话中验证退出/崩溃处理，不在日用锁屏中做破坏性试验。
不能把普通窗口或离屏测试当作安全覆盖，不推断客户端消失后必然释放安全锁。
最后按完整矩阵跨域回归，包括主题变化、缺插件/设备、连续面板开关与 Shell 切换。

## 4. 验收与交接

每次只恢复一个可复核域，不顺手重构其他域。交接记录必须包含：
原始文件和依赖、当前映射、直接复用部分、必要差异及理由、复现步骤、验证结果、
截图/日志位置、未验证项目、恢复点，以及被替代代码的处理。
测试按 [开发约定](../AGENTS.md) 与 [开发流程](development.md) 选择；
新增宿主测试使用 TempEnv，命令断言参数数组，不写真实用户配置。
静态源码检查可辅助发现断链，不能用属性名/目录/函数存在证明交互正确。
